# 监控与告警（Prometheus）

> 对应问题清单项：问题 5（无监控与告警）；任务书 T20260821-005（用户已确认 Prometheus 方案 A）。
> 本服务通过 `GET /metrics` 暴露 Prometheus 文本格式指标（`prometheus-fastapi-instrumentator`），
> 本文档给出指标清单、Prometheus 采集（scrape）配置示例、Alertmanager 告警规则示例，以及指标端点安全建议。

---

## 1. 指标端点概览

| 项 | 值 |
|:---|:---|
| 端点 | `GET /metrics` |
| 是否需要鉴权 | 否（无需 Authorization，Prometheus 抓取不携带 token） |
| 是否参与业务限流 | 否（slowapi 仅作用于显式 `@limiter.limit` 装饰的端点，`RATE_LIMIT_ENABLED` 不影响 /metrics） |
| Content-Type | `text/plain; version=0.0.4; charset=utf-8` |
| 实现 | `prometheus-fastapi-instrumentator==8.1.0` + `prometheus-client==0.21.0` |
| OpenAPI | 不展示（`include_in_schema=False`） |

验证（本机）：

```bash
curl -i http://127.0.0.1:8000/metrics
```

## 2. 指标清单

### 2.1 HTTP 业务指标（`metrics.default()` 默认注册）

| 指标名 | 类型 | 标签 | 说明 |
|:---|:---|:---|:---|
| `http_requests_total` | Counter | `method`, `status`, `handler` | 累计 HTTP 请求数；`status` 默认按 `2xx`/`3xx`/`4xx`/`5xx` 分组 |
| `http_request_duration_seconds` | Histogram | `method`, `handler` | 请求耗时低精度直方图（少量桶 0.1/0.5/1，适合按接口聚合的 SLI） |
| `http_request_duration_highr_seconds` | Histogram | 无 | 请求耗时高精度直方图（0.01~60s 多桶，适合百分位 P95/P99 计算） |
| `http_request_size_bytes` | Summary | `handler` | 请求体大小（Content-Length 头） |
| `http_response_size_bytes` | Summary | `handler` | 响应体大小 |

示例输出片段：

```text
# HELP http_requests_total Total number of requests by method, status and handler.
# TYPE http_requests_total counter
http_requests_total{handler="/health",method="GET",status="2xx"} 2.0
```

### 2.2 进程 / Python 运行时指标（prometheus-client 默认注册表附带，无需额外配置）

| 指标名 | 类型 | 说明 |
|:---|:---|:---|
| `process_cpu_seconds_total` | Counter | 进程累计 CPU 秒 |
| `process_resident_memory_bytes` | Gauge | 进程常驻内存（RSS） |
| `process_start_time_seconds` | Gauge | 进程启动时间（实例存活/运行时长） |
| `python_info` | Gauge | Python 版本信息 |
| `python_gc_*` | Counter | GC 次数 / 回收对象数 |

## 3. Prometheus 采集配置（scrape）

将本服务加入 Prometheus 的 `scrape_configs`（`prometheus.yml` 片段）：

```yaml
global:
  scrape_interval: 15s      # 默认抓取间隔
  evaluation_interval: 15s  # 告警规则评估间隔

scrape_configs:
  - job_name: grid-assistant
    metrics_path: /metrics
    static_configs:
      - targets: ["127.0.0.1:8000"]   # 本服务监听端口（Docker 映射 8000）
        labels:
          instance: grid-assistant-prod
```

若 Prometheus 与本服务同处 docker-compose 网络，`targets` 改用服务名：`["app:8000"]`。
可选地，在 `docker-compose.yml` 追加 Prometheus 服务：

```yaml
  prometheus:
    image: prom/prometheus:v2.53.0
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - ./rules.yml:/etc/prometheus/rules.yml:ro
    command:
      - "--config.file=/etc/prometheus/prometheus.yml"
    ports:
      - "9090:9090"
    restart: unless-stopped
```

## 4. Alertmanager 告警规则示例（>=3 条）

将下列规则保存为 `rules.yml`，并在 `prometheus.yml` 中引用：

```yaml
groups:
  - name: grid-assistant-alerts
    rules:
      # 1) 5xx 比例过高：5 分钟内 5xx 占比 > 10%（持续 3 分钟）
      - alert: GridAssistantHigh5xxRatio
        expr: |
          sum(rate(http_requests_total{status="5xx"}[5m]))
            / sum(rate(http_requests_total[5m]))
            > 0.1
        for: 3m
        labels:
          severity: critical
        annotations:
          summary: "社区网格助手 5xx 比例过高"
          description: "过去 5 分钟 5xx 占比 {{ $value | humanizePercentage }}，超过 10%。"

      # 2) 接口 P95 耗时过高：5 分钟内 P95 > 3s（持续 5 分钟）
      - alert: GridAssistantHighLatencyP95
        expr: |
          histogram_quantile(
            0.95,
            sum(rate(http_request_duration_highr_seconds_bucket[5m])) by (le)
          ) > 3
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "社区网格助手 P95 耗时过高"
          description: "过去 5 分钟 P95 耗时 {{ $value }}s，超过 3s。"

      # 3) 实例存活：目标不可达（持续 1 分钟）
      - alert: GridAssistantInstanceDown
        expr: up{job="grid-assistant"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "社区网格助手实例不可达"
          description: "{{ $labels.instance }} 已被 Prometheus 探活失败超过 1 分钟。"

      # 4) 事件处理失败率：事件提交/处理失败占比 > 20%（预留规则）
      #    当前版本未暴露业务指标；后续在业务侧注册 grid_agent_events_total 与
      #    grid_agent_events_failed_total（Counter）后启用本规则。
      - alert: GridAssistantEventFailureRate
        expr: |
          sum(rate(grid_agent_events_failed_total[5m]))
            / sum(rate(grid_agent_events_total[5m]))
            > 0.2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "社区网格助手事件处理失败率过高"
          description: "过去 5 分钟事件处理失败率 {{ $value | humanizePercentage }}，超过 20%。"
```

Alertmanager 接收配置示例（`alertmanager.yml`，通知渠道可按需替换为钉钉/企微/邮件 webhook）：

```yaml
route:
  receiver: default
  group_by: ["alertname"]
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
receivers:
  - name: default
    webhook_configs:
      - url: http://127.0.0.1:9093/webhook  # 替换为真实通知 webhook
```

## 5. 指标端点安全建议

1. **限制访问来源**：`/metrics` 无鉴权，生产环境应在反向代理（Nginx）按网段限制——仅放行 Prometheus 所在内网/运维网段，拒绝公网访问，避免业务指标（请求量/耗时/大小）泄露（Nginx 限制示例见 `deploy/nginx.conf` 的 `location = /metrics`）。
2. **不开放业务端口到公网**：本服务 8000 端口的安全组入方向仅放行本机/内网（见 deploy/DEPLOY.md「6.1 防火墙」），公网流量一律经 Nginx 反代进入。
3. **控制抓取频率**：`/metrics` 不参与业务限流，抓取频率由 Prometheus `scrape_interval` 控制（默认 15s），勿高频抓取。
4. **监控组件自身安全**：Prometheus/Alertmanager 若同机部署，绑定内网网卡（如 `--web.listen-address=127.0.0.1:9090`）或置于独立内网；告警通知渠道的 token/密钥走环境变量或 secret 管理，不写入代码仓库。
5. **多副本部署注意**：多进程/多副本时需按官方配置 `PROMETHEUS_MULTIPROC_DIR`（多进程模式）避免指标互相覆盖；当前单实例部署无需配置。
