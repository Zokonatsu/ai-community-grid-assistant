## 一、需求（已由用户确认）
**一句话目标**：居民在事件列表对自己提交的事件，提交后 5 分钟内（且为「处理中/待审核」未终态）最右侧显示可点击的「撤销」按钮；撤销后事件标记为「已撤销」并保留记录；超过 5 分钟或已进入终态时按钮变灰不可点、显示「已执行」。

**可测试验收标准**
1. 居民端事件列表最右侧新增「操作」列；自己的事件在提交后 5 分钟内且状态为「处理中」或「待审核」时，显示可点击的「撤销」按钮。
2. 点击撤销成功 → 事件状态变为「已撤销」，记录保留（居民与后台列表仍可见该事件），操作列不再显示撤销按钮而是「已撤销」标识。
3. 超过 5 分钟（距 created_at > 300 秒）→ 按钮变灰、不可点击、文案显示「已执行」；页面无需手动刷新，到 5 分钟边界按钮应自动变为灰/已执行。
4. 终态事件（已派单/已完成/已受理/处理超时/处理失败/已拒绝）即使 5 分钟内也显示灰按钮「已执行」，不可撤销。
5. 管理后台事件列表不显示撤销按钮、不提供撤销能力；但仍能看到「已撤销」状态的事件（保留记录可追溯）。
6. 后端为权威校验：非本人撤销 → 403；事件不存在 → 404；非未终态 → 400+文案；超 5 分钟 → 400+文案；均不得改变事件状态。
7. 「已撤销」状态稳定：后台异步处理（_process_event 成功/超时/异常分支）不得把已撤销事件改写为已完成/处理超时/处理失败。

## 三、冻结契约
**新接口：`POST /api/events/{event_id}/cancel`**（需登录 Bearer token，无请求体）
- 校验顺序与响应（沿用现有 HTTPException 风格）：
  | 场景 | 状态码 | 响应 detail（精确匹配） |
  |---|---|---|
  | 事件不存在 | 404 | `事件不存在` |
  | 非本人（含管理员代撤销） | 403 | `无权操作该事件` |
  | 状态非「处理中/待审核」 | 400 | `仅处理中或待审核的事件可撤销` |
  | 距 created_at 超过 300 秒（或 created_at 解析失败，防御） | 400 | `已超过5分钟，无法撤销` |
  | 成功 | 200 | `{"success": true, "data": {"event_id": "<id>", "status": "已撤销"}}` |
- 归属判定：`current_user.id == task.user_id` 才允许；管理员即使调用也返回 403。
- 5 分钟判定：`datetime.now() - datetime.strptime(task["created_at"], "%Y-%m-%d %H:%M:%S") > timedelta(seconds=300)` → 拒绝；解析异常按超时处理。
- 成功后：在 `_task_lock` 内 `task["status"] = "已撤销"` 并 `_save_tasks(_tasks)`；不清除 replies/handler 等既有字段（保留记录）。

**状态语义**
- 新增状态 `已撤销`；可撤销状态集合 = {处理中, 待审核}；终态集合（按钮灰+「已执行」）= {已派单, 已完成, 已受理, 处理超时, 处理失败, 已拒绝}。
- `GET /api/events` 无需改动：已撤销事件照常返回（status=已撤销，记录完整保留）。
- `_process_event`：成功分支已有 `if task["status"] == "处理中"` 守卫（保持）；超时/异常分支需新增守卫——仅当 status ∈ {处理中, 待审核} 时才改写为处理超时/处理失败，否则跳过（防止覆盖「已撤销」）。

**前端行为契约（static/index.html）**
1. 表格新增最右侧列「操作」（thead 与每行 tbody 同步）。
2. 每行操作列规则（按 e.status 与当前时间距 e.created_at 计算）：
   - `e.status === '已撤销'` → 显示「已撤销」标签，不显示按钮。
   - `e.status ∈ {处理中, 待审核}` 且 距 created_at ≤ 300 秒 → 显示可点击「撤销」按钮。
   - 其它（终态 或 超过 300 秒）→ 显示灰色禁用按钮，文案固定「已执行」。
3. 5 分钟边界自动失效：页面加载后无需刷新，按钮应在超过 300 秒时自动变为灰/「已执行」（实现可用本地定时器按 created_at 周期重算，建议 ≤60 秒周期）。
4. 点击「撤销」→ `fetch POST /api/events/{event_id}/cancel`（带 Bearer）；成功 → 重新调用 loadList() 刷新；失败（400/403/404）→ 以 alert 或内联提示展示后端 detail，并刷新列表。
5. `statusClass` 增加 `已撤销` 分支（建议 tag-cancelled 样式，可新增对应 CSS 到 common.css 或 index.html 内联样式）。
