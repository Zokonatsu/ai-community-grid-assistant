## 一、需求（已确认）
**一句话目标**：将 `main.py` 中 `allow_origins=["*"]`（配合 allow_credentials=True 的失控 CORS）收紧为环境变量白名单，默认允许来源含本机与生产前端 `http://118.31.58.191:8000`，上线前无需改码即可配置。

**已核实的现状**：main.py 注册 CORSMiddleware，`allow_origins=["*"]`、`allow_credentials=True`、`allow_methods=["*"]`、`allow_headers=["*"]`。

**可测试验收标准**
1. 默认配置（未设 CORS_ALLOW_ORIGINS）下：请求带 `Origin: http://118.31.58.191:8000` → 响应含 `access-control-allow-origin: http://118.31.58.191:8000`；带 `Origin: http://evil.example.com` → 响应不含 ACAO 头；本机 127.0.0.1:8000 / localhost:8000 同样放行。
2. 设 `CORS_ALLOW_ORIGINS=https://a.example.com, https://b.example.com` 后：a/b 放行，默认 118.31.58.191 不再放行。
3. `CORS_ALLOW_ORIGINS=*` 时：allow_credentials 置 false（避免通配+凭据的浏览器拒绝），并记录 warning 日志；默认配置绝不出现 `allow_origins=["*"]`。
4. `.env.example` 增加 CORS_ALLOW_ORIGINS 说明；README 与 deploy/DEPLOY.md 上线前检查项同步。
5. 新增/更新 CORS 测试（tests/test_cors.py 或并入现有文件）覆盖 1-3；run_regression core/full 全绿。

## 二、范围

## 三、冻结契约
- 新增环境变量：`CORS_ALLOW_ORIGINS`（逗号分隔，允许空格，逐项 trim；空项忽略）。未设置时默认值 `http://127.0.0.1:8000,http://localhost:8000,http://118.31.58.191:8000`。
- main.py：allow_origins 取自 config（列表）；列表含 `*` 时 allow_credentials=False + warning；否则 allow_credentials=True；allow_methods/allow_headers 保持 ["*"]。
- 响应行为（可测试）：放行 origin → 回显该 origin 的 ACAO 头；未放行 origin → 无 ACAO 头。
- 默认配置下源码中不得存在 `allow_origins=["*"]`。
