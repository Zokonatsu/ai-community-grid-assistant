## 一、需求（已确认，用户选择 C 字段级加密）
**一句话目标**：对 `data/events.jsonl` 与 `data/tasks.json` 中的敏感字段做 AES-256-GCM 字段级加密（复用 `DATA_ENCRYPTION_KEY`），存量明文兼容读取并附一次性迁移脚本，使服务器被入侵时无法直接读到敏感业务数据明文。

**已核实的现状**
- `data/events.jsonl`（11,679 B）与 `data/tasks.json`（32,666 B）当前为明文 JSON；tasks.json 含 `user_phone`、`user_id_card`、`beneficiary_phone` 等高度敏感字段；两者均含 description/address/reply/user_id/定位。
- 写入路径：`main.py:_save_tasks`（tasks.json 全量 dump，L71-80）；`record_agent.record_node`（events.jsonl 追加，record_agent.py L157）。
- 读取路径：`main.py:_load_tasks`（L54-68，启动加载进内存 `_tasks`；事件列表/管理端均由内存数据驱动，API 响应在此之后生成）。
- 账号数据已用 `secure_store.py`（AES-256-GCM + `DATA_ENCRYPTION_KEY`，含 encrypt/decrypt/load_encrypted/save_encrypted，kind 隔离 AAD）。

**可测试验收标准**
1. 新写入事件落盘后，tasks.json/events.jsonl 的加密字段值均为 `enc:v1:` 前缀密文；用明文关键词（如提交的 description 内容、真实手机号）在全仓 data/ 下 grep 不到；非敏感字段保持明文。
2. 存量明文文件（无 enc:v1:）直接启动服务：`GET /api/events` 与管理端接口返回与加密前一致的明文数据（兼容读取）；任一次 `_save_tasks` 后文件自动升级为密文。

## 三、冻结契约
### 3.1 字段级加解密 helper（secure_store.py 或新模块）
- `encrypt_field(value: str) -> str`：非空字符串 → `enc:v1:<base64>`；空串/None 原样返回（不加密）。密钥 = `DATA_ENCRYPTION_KEY`（AES-256-GCM），AAD 使用独立 kind 域（如 `"field"`）与账号数据隔离。
- `decrypt_field(value: str) -> str`：以 `enc:v1:` 开头 → 解密还原原值；否则视为明文原样返回（存量兼容）。
- 数值字段（event_lat/event_lng/lat/lng）：加密后为 `enc:v1:` 字符串存储；解密后还原为原数值类型（float）或 None。

### 3.2 加密字段清单（非空才加密）
- tasks.json：`description`、`address`、`reply`、`user_name`、`user_phone`、`user_id_card`、`beneficiary_name`、`beneficiary_phone`、`beneficiary_building`、`beneficiary_unit`、`beneficiary_room`、`event_lat`、`event_lng`。
- events.jsonl：`description`、`address`、`reply`、`user_id`、`lat`、`lng`。

### 3.3 读写路径
- 写：`_save_tasks` 落盘前对上述字段加密；`record_agent.record_node` 追加前对上述字段加密。
- 读：`_load_tasks` 加载后立即解密，内存 `_tasks` 保持明文（API/管理端逻辑零改动）；events.jsonl 仅追加写入（现有读取方只有测试/自检，如需读取按同一规则解密）。

### 3.4 迁移脚本
- `scripts/migrate_events_encryption.py`：子命令 `--dry-run` / 默认执行；对 data/events.jsonl + data/tasks.json 逐字段加密；已 `enc:v1:` 跳过；执行前备份到 `data.bak.<时间戳>/`（不匹配 scan_secrets 的残留规则，脚本结束不得残留）；输出每文件加密字段数摘要；DATA_ENCRYPTION_KEY 缺失/非法时退出非 0。
