## 三、冻结契约

### 3.1 ci.yml
- 触发：`on: [push, pull_request]`（全分支；如需收紧可后续改为 main）。
- job regression（ubuntu-latest）：
  1. actions/checkout@v4
  2. actions/setup-python@v5，python-version 3.12
  3. `pip install -r requirements.txt`
  4. `python -m pytest tests --collect-only -q`（收集 sanity，可选但建议）
  5. `python tests/run_regression.py core`（11 个 P0；失败即 job 失败）
- job frontend-security（ubuntu-latest）：
  1. actions/checkout@v4
  2. actions/setup-python@v5（3.12）+ actions/setup-node@v4（node 20，供 node --check）
  3. `python scripts/check_frontend_js.py`
  4. `python scripts/scan_secrets.py`
- 两 job 均不注入任何 secrets/env 密钥。

### 3.2 cloud-integration.yml
- 仅 `on: workflow_dispatch`（无 push/PR 触发）。
- 步骤：checkout → setup-python → pip install -r requirements.txt → env 从 `secrets.COS_REGION / COS_BUCKET / COS_SECRET_ID / COS_SECRET_KEY / DATA_ENCRYPTION_KEY` 注入，`AUTH_STORE=cloudbase` → `python scripts/verify_cloud_integration.py`。
- README 注明：使用前需在 GitHub 仓库 Settings→Secrets 配置上述 5 个变量（不含真实值于仓库文件）。

### 3.3 check_frontend_js.py
- 页面：`static/index.html`、`static/login.html`、`static/admin.html`。
- 提取所有无 `src` 的内联 `<script>...</script>` 内容，写临时 `.js`，逐个 `node --check`；任一失败 → 退出码非 0 并列出页面/文件名。

### 3.4 scan_secrets.py
- 扫描范围：仓库内所有文件，排除 `.git`、`.venv`、`__pycache__`、`.codex`、`.claude`、`node_modules`、`_*_backup_*` / `*_planner_backup_*` / `_dev01_backup_*` 目录；**排除 `.env` 本身**。
- 检查 1：`git check-ignore .env` 必须命中（.env 不入库）。
- 检查 2：占位 pattern 命中即失败（不打印真实值，只报文件与 pattern 名）：
  - `COS_SECRET_(ID|KEY)\s*[:=]`
  - `DATA_ENCRYPTION_KEY\s*[:=]\s*[0-9a-fA-F]{32,}`
  - `AKID[0-9A-Za-z]{20,}`（腾讯云 SecretId 常见前缀）
- 无命中 → 退出 0。

### 3.5 verify_cloud_integration.py
- 仅操作临时对象 `_ci_verify_<uuid>.enc`：`ensure_bucket()` → `upload(encrypt("ci-verify", {"ts":...}))` → `download`+`decrypt` 比对 → `delete_object`。

- 可离线单测（mock _get_client）验证逻辑，真实云端由 workflow_dispatch 执行。
