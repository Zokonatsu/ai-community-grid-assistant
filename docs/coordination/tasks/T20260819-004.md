## 三、冻结契约
**云端对象布局（cloudbase 模式）**
| 对象 key | 内容 | 加密 |
|---|---|---|
| `users.json.enc` | 用户表 JSON（现有 `_users` 结构） | secure_store.encrypt("users", data)，AES-256-GCM |
| `sessions.json.enc` | 会话表 JSON（现有 `_sessions` 结构，token→{token,user_id,created_at}） | secure_store.encrypt("sessions", data)，AES-256-GCM |

- 存储桶：`COS_BUCKET`（.env），地域 `COS_REGION`；创建时私有权限（默认 ACL，不开放公共读/写）。
- 读取语义与本地一致：对象不存在 → 空 `{}`；网络/鉴权/解密异常 → fail-fast 抛错，绝不静默空库（防止误重建 admin 覆盖真实数据）。

**会话读写分发（auth.py）**
- `_load_sessions()`：file → `_load_json("sessions", SESSIONS_FILE)`；cloudbase → `decrypt("sessions", cloud_store.download(SESSIONS_OBJECT_KEY))`（None → `{}`）。
- `_save_sessions(data)`：file → `_save_json(...)`；cloudbase → `cloud_store.upload(SESSIONS_OBJECT_KEY, encrypt("sessions", data))`。
- 替换点（必须全部替换，不得残留直接 `_save_json("sessions", ...)` 写本地）：`_init_auth`、`login_user`、`logout_user`、`get_current_user`（过期清理）、`_cleanup_expired_sessions`。

**启动初始化（cloudbase）**
- `_init_auth`：先 `cloud_store.ensure_bucket()`（桶缺失自动创建，失败则启动报错并给出不含密钥的提示）→ `_load_users()` → `_load_sessions()` → 空库自动重建 admin/admin123456（现有逻辑，auth.py:196-221）→ `_save_users()` / `_save_sessions()` 上云。

**初始化脚本（init_cloud_storage.py）行为契约**
- 幂等可重跑；执行顺序：建桶 → 清空云端两对象（存在才删）→ 删除本地身份/会话加密文件与遗留明文/迁移备份 → 摘要输出（桶名/对象是否删除/本地删除文件数，**不含任何密钥**）。
- 危险操作需二次确认：无参数运行进入交互确认；`--yes` 显式跳过确认（供自动化/文档化流程）。
- 删除路径仅限：`secure/users.json.enc`、`secure/sessions.json.enc`、`data/users.json`、`data/sessions.json`、项目内 `*.migrated.bak`；不得触碰 data/events.jsonl、tasks.json、community_config.json。

**本地开发/测试隔离**
- 因 `config.py:19` `load_dotenv(override=False)` 会读取 .env，.env 切 cloudbase 后，**所有 tests/test_*.py 必须在 import config/auth/main 之前** `os.environ["AUTH_STORE"] = "file"`（逐文件补齐，含 test_auth/test_comprehensive/test_security_fixes/test_register_location/test_event_cancel/test_data_isolation/test_proxy_beneficiary/test_scene_tag/test_community_center/test_resident_review_location/test_semantic_timeout/test_input_validation/test_life_rescue_fix/test_server 等实际 import auth/main 的文件）。

**安全**
