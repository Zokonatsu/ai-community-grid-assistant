## 一、需求（已由用户确认）
**一句话目标**：管理员输入正确密码登录后，不再进入事件提交首页 `index.html`，直接跳转到管理后台 `admin.html`；居民登录行为不变，仍跳首页。

**可测试验收标准**
1. 使用 role=admin 的账号在 `login.html` 登录成功 → 浏览器地址栏跳转到 `/admin.html`（管理后台），不再进入 `/`。
2. 使用 role=resident 的账号登录成功 → 仍跳转 `/`（index.html），行为与现在完全一致。
3. 登录失败（密码错误等）、网络异常等错误分支的提示与停留页面行为保持不变。
4. 管理后台原有能力不变：后台无 token 跳 `login.html`、非 admin 跳 `/` 的守卫、返回首页/退出功能均不修改；首页管理员「管理后台」入口（admin-link）保留。

- 修改点：`handleLogin` 中登录成功分支的跳转目标（现 `static/login.html:192` 固定 `window.location.href = '/'`）。

**明确不做**
- 不改后端：`auth.py`、`main.py`、`/api/auth/login` 接口、INTERFACE.md 均不动（登录响应已含 `user.role`，见 auth.py `_public_user`）。

## 三、冻结契约
**接口基线（只读消费，不改）**：`POST /api/auth/login` 已返回的 `data.data.user.role`（string，必填，取值 `resident` | `admin`），登录响应结构 `data.data.token`（string）、`data.data.user`（object）。

**前端行为契约（本次冻结）**：在 `static/login.html` 的 `handleLogin` 内，`data.success === true` 时：
1. 保留现有 `localStorage.setItem('token', data.data.token)` 与 `localStorage.setItem('user', JSON.stringify(data.data.user))`。
2. 按角色分流跳转：
   - `data.data.user.role === 'admin'` → `window.location.href = '/admin.html'`
   - 其它（`resident`，含兼容未知值）→ `window.location.href = '/'`（保持现行为）
3. 其余分支（`!data.success`、异常 catch、按钮 loading 状态）逻辑不变。
