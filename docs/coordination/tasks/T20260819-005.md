## 一、需求（已由用户确认）
**一句话目标**：管理员回复事件后，居民端事件列表无需手动刷新即自动出现「未读回复」红点（沿用现有状态格小红点 ●）；居民查看回复并关闭弹窗后红点消失。

**可测试验收标准**
1. 居民端事件列表在页面打开期间按固定间隔（15 秒）自动重新拉取 `GET /api/events` 并重新渲染；管理员回复后 ≤15 秒内，对应事件的「请点击查看人工的回复」旁自动出现红点 ●，无需手动刷新。
2. 查看回复并关闭弹窗后红点消失（现有 `closeReplyDialog → markRead → loadList` 行为保持）。
3. 轮询与现有交互不冲突：回复弹窗打开期间不触发列表刷新；不产生重复定时器；不影响提交轮询面板、30 秒撤销按钮定时器、markRead 刷新。
4. 轮询请求失败（非 401）时不覆盖现有列表（保留当前内容，可 console 记录），避免瞬时错误清空界面；401 仍走现有 `checkUnauthorized` 逻辑。
5. 红点样式沿用现有 `unread-badge`（不新增独立红点/汇总角标/样式）。
6. 未读语义不变：仅「管理员有回复」且 `has_new_reply=true` 的事件显示红点（后端逻辑不动）。
7. 管理端、后端、接口零改动；`GET /api/events` 响应结构不变。

## 三、冻结契约
**轮询行为（static/index.html）**
- 轮询间隔：**15 秒**（常量如 `POLL_LIST_MS = 15000`）。
- 触发：页面初始化成功加载列表后启动；每 15 秒调用一次 `loadList()`（复用现有函数，不改其渲染逻辑）。
- 暂停条件：`replyOverlay` 可见（回复弹窗打开）期间不触发刷新，关闭后恢复；`document.hidden` 时可选暂停（非强制）。
- 失败处理：轮询请求失败（网络错误/非 2xx 且非 401）时**保留现有列表内容**，不写入「加载失败」覆盖；401 沿用现有 `checkUnauthorized(res)` 跳登录逻辑。
- 定时器管理：单实例——启动前 `clearInterval` 已有列表轮询定时器，避免重复；页面卸载（beforeunload/unload）时清理（可选）。
- 与现有定时器关系：保留现有 30 秒撤销按钮重算定时器不动；新增列表轮询定时器与之并存（loadList 本身会整体重渲染，含操作列，两者无冲突）。

**红点与已读**
- 红点：沿用 `statusCell` 中 `unread-badge`（`has_new_reply` 为 true 时渲染 ●），无样式改动。
- 已读：查看关闭弹窗 → `markRead` → `loadList()`（现有逻辑保持）；轮询刷新不得覆盖未完成的 markRead 请求结果（同一事件最后写 `user_read_at` 生效即可，无需额外处理）。

**不做后端改动确认**
- `GET /api/events` 仍返回 `has_new_reply`（main.py:590-598 语义）；`POST /api/events/{id}/mark_read`（main.py:1307-1324）不变；`POST /api/events/{id}/reply`（main.py:1272-1290）不变。
