## 一、需求（已由用户确认）
**一句话目标**：注册用户必须获取定位且定位在小范围覆盖内（距社区中心 ≤ radius_m）才允许注册；无定位或越界一律拒绝，且该限制强制开启、不可关闭。

**可测试验收标准**
1. 无坐标注册（register_lat/register_lng 缺失或为 null）→ 接口返回 `success=false` + 固定错误文案「注册需先获取定位，请允许浏览器定位权限后重试」，不创建用户。
2. 坐标越界（距当前生效中心 > radius_m）→ 返回 `success=false` + 固定错误文案「当前定位不在小区范围内，无法注册」，不创建用户。
3. 坐标在范围内（≤ radius_m）→ 注册成功，`data.user.location_status === "verified"`。
4. 半径读取：使用当前生效配置（优先 `data/community_config.json` 持久化值，未配置时回退环境变量默认 500m），即 `geo.get_community_config()` 的取值，后台改半径后立即生效。
5. 限制强制开启：不新增「关闭限制」开关；HTTP 注册路径与 `auth.register_user` 域逻辑均执行校验。
6. 仅新注册受影响：存量已注册用户数据、登录、`list_users` 等后台展示逻辑不变。
7. 前端：login.html 注册表单在未定位（reg-lat/reg-lng 为空）时阻止提交并提示；后端返回的错误文案在 register-error 区域展示（不跳转）。
8. 管理员角色注册仍被禁止（现有「禁止通过注册创建管理员账号」逻辑不变）。

## 三、冻结契约
**接口基线（本次变更）**：`POST /api/auth/register`
- 请求：现有字段不变；`register_lat: float|null`、`register_lng: float|null` 语义由「可选」改为「业务必填」——缺失或 null 时服务端返回业务错误而非 422（schema 保持可空，避免前端传 null 触发校验错误）。
- 成功响应不变：`{"success": true, "data": {"user": {...}}, "error": "注册成功，请登录"}`，其中 `user.location_status` 必为 `"verified"`。
- 失败响应（新增两类，`success=false`，HTTP 200 与现有 AuthResponse 一致）：
  | 场景 | error 文案（精确匹配） |
  |---|---|
  | 无坐标（lat/lng 任一为 None） | `注册需先获取定位，请允许浏览器定位权限后重试` |
  | 坐标越界（> radius_m） | `当前定位不在小区范围内，无法注册` |
- 半径来源：`geo.get_community_config()` 当前生效值（持久化优先，环境变量兜底默认 500m）；判定用 `geo.is_within_community(lat, lng)` 返回的 `within`。

**域逻辑契约（auth.register_user）**：在用户名/密码/实名/手机/身份证/角色/楼栋单元房间校验通过、用户名与手机号查重之后：
1. `register_lat is None or register_lng is None` → 返回 `(False, "注册需先获取定位，请允许浏览器定位权限后重试", None)`。
2. `geo.is_within_community(register_lat, register_lng)[0] is False` → 返回 `(False, "当前定位不在小区范围内，无法注册", None)`。
3. 通过 → 正常创建用户，`location_status="verified"`（仍可用现有 verified/unverified 计算，结果恒为 verified）。

**前端行为契约（static/login.html）**：
1. 注册表单提交时（handleRegister）：若 `reg-lat` 或 `reg-lng` 为空 → 阻止提交，在 register-error 展示「注册需先获取定位，请允许浏览器定位权限后重试」。
2. 已定位则正常提交；后端 `success=false` → register-error 展示后端 error 文案（现有逻辑保持）。
3. 定位按钮/状态文案改为必填语义（如「必须定位（需在小区范围内）才能注册」），`getPosition` 的 6s 超时与失败降级逻辑保留，仅提交校验变严。

**对存量影响**：不修改已存用户记录；`status`、`location_status` 展示与列表逻辑不变。
