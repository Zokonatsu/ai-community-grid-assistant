## 三、冻结契约

### 3.1 脚本改造模式（每个脚本统一）
1. 顶部保留（或由 conftest 保证）环境固定：`AUTH_STORE=file`、`DATA_ENCRYPTION_KEY`（64 hex）、LLM 变量。
2. **禁止模块顶层 `sys.exit()`**：所有退出逻辑只放在 `if __name__ == "__main__":` 分支。
3. 原有「模块顶层 setup_test_env()/teardown_test_env()」调用**迁移**：
   - pytest 模式：由 conftest 的 module 级 autouse fixture 提供备份/恢复，脚本内不再重复执行数据目录切换；
   - 直跑模式：`if __name__ == "__main__":` 内按「备份→新建空目录→运行→finally 恢复」调用（保留脚本自足性）。
4. 现有校验/运行逻辑包装为可被 pytest 收集的 `test_*` 函数（如 `def test_suite():`）：内部逐项断言，失败时以 pytest 断言/异常呈现（保留原 check 明细输出）；直跑入口调用同一函数并按结果 `sys.exit(0/1)`，保证「pytest 与直跑走同一套校验」。
5. 读取 data/secure 的模块（auth/main）初始化必须在数据隔离生效之后（测试函数内 `importlib.reload` 或延迟导入），禁止依赖模块顶层 import 时真实数据目录的状态。
6. `test_server.py`：加 `@pytest.mark.server` 并默认 skip（如 `pytestmark = pytest.mark.skip(reason="远程部署冒烟，非本地回归")`），直跑能力保留。

### 3.2 conftest.py 契约
- 模块导入期（早于任何 test 模块）设置：`AUTH_STORE=file`、`DATA_ENCRYPTION_KEY`（64 hex 测试值）、`LLM_API_KEY`、`LLM_BASE_URL`；不读取 .env。
- module 级 autouse fixture `data_isolation`：
  1. 清理上次残留 `data.bak.*`/`secure.bak.*`（防上次崩溃残留）；
  2. 备份当前 `data/`、`secure/`（改名到独立备份目录，命名不匹配 pytest/runner 清理规则）；
  3. 新建空 `data/`、`secure/`；
  4. yield 运行测试；
  5. finally：删除临时空目录 → 恢复备份目录 → 断言无残留 `*.bak.*`。
- 提供 1-2 个公共 helper fixture（如 `resident_pair`：A/B 两居民 token，供越权测试；本期最小实现，T-B 扩展）。

### 3.3 run_regression.py 契约
- `core` profile（高价值快速集，P0）：test_auth、test_security_fixes、test_data_isolation、test_cloud_store、test_register_location、test_event_cancel、test_comprehensive、test_semantic_timeout、test_input_validation。
- `full` profile：全部 16 个（test_server 默认 skip）。
- 输出：逐脚本 通过/失败 + 耗时；汇总（N 通过 / M 失败 / 总耗时 / 残留备份检查=无）；任一失败退出码非 0。
- 可用 `pytest.main([...])` 或子进程调用 pytest；严禁并行执行多个脚本（串行，避免数据目录互踩）。

### 3.4 pytest.ini
- `python_files = test_*.py`、`testpaths = tests`、`markers`（core/full/server）、`addopts = -p no:cacheprovider`（CI 友好）。

### 3.5 安全
- 任何新增/改造文件不得包含密钥明文；日志/输出只含非敏感信息。
