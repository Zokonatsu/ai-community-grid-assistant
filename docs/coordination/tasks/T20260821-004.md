## 一、需求（已确认，采用推荐默认参数）
**一句话目标**：引入 slowapi 限流（登录/注册、事件提交）与 LLM 调用指数退避重试 + 熔断器，突发流量或 LLM API 长时间故障时服务自我保护、降级不崩。

**已核实的现状**：全仓无 slowapi/tenacity/熔断/限流实现；`receive_agent._call_llm_once`（L189-209）单次调用 OpenAI SDK，失败即抛异常，由 receive_node 既有 try/except（L554 起）降级「待审核」。

**可测试验收标准**
1. 登录/注册限流 5 次/分钟/IP：第 6 次 → HTTP 429 + JSON `{"detail": "请求过于频繁，请稍后再试"}`。
2. `POST /api/events` 限流 10 次/分钟/用户（keyfunc=token 内 user_id，无 token 按 IP）：超限 → 429 同上。
3. LLM 熔断：mock `_call_llm_once` 连续失败 ≥5 次 → 熔断 open（默认 60s）；open 期间不再调用 LLM（mock 调用计数不变）且事件按既有降级路径落「待审核」；cooldown 到期自动半开/恢复（有测试验证恢复尝试）。
4. LLM 退避重试：瞬时失败（连接/超时/限流/5xx 类）自动重试 2 次，退避 1s/2s（测试用短退避覆盖或 mock 时间）。
5. 既有行为不回归：正常路径、API 超时降级、硬规则、无效输入等全部保持；run_regression core/full 全绿（测试环境通过 RATE_LIMIT_ENABLED=false 或高阈值关闭限流干扰，另有专门测试显式开启验证）。
6. 配置与文档：.env.example、README、deploy/DEPLOY.md 记录新变量与 429 行为；INTERFACE.md 增补限流说明。

## 三、冻结契约
### 3.1 环境变量（config.py，含默认值）
| 变量 | 默认 | 说明 |
|---|---|---|
| RATE_LIMIT_ENABLED | true | false 时跳过限流（测试环境用） |
| RATE_LIMIT_LOGIN | 5/minute | 登录/注册，keyfunc=客户端 IP |
| RATE_LIMIT_EVENTS | 10/minute | POST /api/events，keyfunc=Bearer user_id，无 token 按 IP |
| LLM_RETRY_ATTEMPTS | 2 | LLM 调用重试次数 |
| LLM_RETRY_BASE_DELAY | 1.0 | 退避基数秒（1s/2s） |
| LLM_CIRCUIT_THRESHOLD | 5 | 连续失败次数达阈值熔断 open |
| LLM_CIRCUIT_COOLDOWN | 60 | 熔断保持秒数 |

### 3.2 429 响应
- HTTP 429 + JSON `{"detail": "请求过于频繁，请稍后再试"}`（slowapi 自定义 exception handler，全局统一）。

### 3.3 熔断/重试
- 重试仅覆盖瞬时类异常（连接错误、超时、429/限流、5xx）；业务解析类异常（JSON 解析失败、模型返回非 dict）不重试。
- 熔断器作用于 LLM 调用入口（receive_agent 多轮采样循环之外包一层）；open 期间直接返回降级结果（走既有「待审核 / confidence=none」路径），不触发真实调用。
- 熔断状态/计数打日志（logger），可观测。

### 3.4 测试环境
- `tests/conftest.py` 设 `RATE_LIMIT_ENABLED=false`（默认）保证既有回归不受 429 干扰；新增测试文件内显式启用限流/熔断（monkeypatch 短阈值/短退避）验证 429 与熔断降级。
