# 记忆管理（任务收尾 · 两轨道）

> 原则：任务结束后的信息**先分流、再入库**。临时状态自动消亡，可复用经验经提炼后入长期记忆；
> 每条长期记录必须带**来源**与**时效**，并受**有效期/衰减**约束；
> **敏感数据一律不进记忆**（硬性底线）。

## 1. 两条轨道

| 轨道 | 存放 | 内容 | 生命周期 |
|---|---|---|---|
| 临时 temp | `docs/coordination/memory/temporary/` | 任务中间状态：进度、待办、临时结论、过程草稿 | 保留期（默认 7 天，可配置 TTL）到期**自动清理**，不进长期记忆 |
| 长期 longterm | `docs/coordination/memory/longterm/` | 可复用经验：踩坑、约定、部署要点、验收结论、决策依据 | 必须带 来源+有效期；受衰减约束；到期标记 deprecated |

> `docs/coordination/memory/` 为运行时数据，已加入 `.gitignore`，不进版本库。

## 2. 写入门槛（长期轨道，缺一不可）

1. **提炼**：从任务日志/测试报告/复盘浓缩为一条可复用的结论，含「触发场景 + 处理方式」，不粘贴原始日志。
2. **去重**：内容哈希或相似度比对——与既有记录相同/高度相似则跳过或更新，不重复存储。
3. **冲突检查**：同主题（tags 有交集）结论不同 → 新记录标记 `conflict` 并关联旧记录，**人工裁决**，不静默覆盖。
4. **来源**：每条必须带 `source`（哪个 Agent / 哪份日志 / 哪次验收），无来源拒绝写入。
5. **时效**：每条必须带 `valid_until`（默认 90 天，可配置）。

## 3. 有效期与衰减机制

- **临时轨道**：按保留期 `ttl_seconds`（默认 604800 = 7 天）到期自动删除；`memory.py clean` 执行清理。
- **长期轨道**：
  - 每条带 `valid_until`，到期后状态置 `deprecated`（不硬删，保留可追溯）；
  - 衰减：`score` 按天指数衰减（默认 rate=0.05/天，约 20 天半衰）；
  - `score < 0.2` 的记录在列表/检索中降级展示并提示「低时效，建议复核」；
  - 定期执行 `memory.py clean` 完成「清理过期 + 衰减复核 + 过期标记」。
- 检索/汇报时：active 优先、conflict 标注、deprecated 置底，避免用过时经验误导决策。

## 4. 敏感数据底线（硬性，临时与长期均适用）

- **不进记忆**：API 密钥、密码、token、云凭据（COS_SECRET 等）、手机号、身份证号等。
- `memory.py` 内置敏感模式检测，命中即**拒绝写入**；如确需留痕，只允许存「引用位置」（例如：见项目 .env / 见 docs/...），**不存值**。
- 本条无例外、无强制开关。

## 5. 触发时机

- 任务结束时（tester 通过/失败、planner 验收 accepted、developer 修复完成）由对应 Agent 执行：
  - 中间状态/临时结论 → `add temp`（带 TTL）；
  - 可复用经验/踩坑/约定 → 提炼后 `add longterm`（带 source + valid-days）。
- 任务启动时或定期执行 `clean`，保证记忆库不过期堆积。

## 6. 命令速查

    python scripts/memory.py add temp --content "..." [--ttl-seconds 604800]
    python scripts/memory.py add longterm --content "..." --source "..." [--valid-days 90] [--tags a,b] [--confidence high|medium|low]
    python scripts/memory.py clean [--dry-run]
    python scripts/memory.py list
    python scripts/memory.py search <关键词>
